# C++ Code Checker

**IDE:** Visual Studio Code  
**Author:** [Соболева Екатерина Владимировна]  
**Group:** [М3120]

C++ Code Checker — расширение Visual Studio Code для статического поиска некоторых распространённых ошибок и проблем стиля в исходном коде C++.

## Возможности

- анализ текущего C++ файла по команде `C++ Code Checker: Analyze Current File`;
- автоматический анализ при открытии, сохранении и изменении документа;
- диагностика в редакторе и панели Problems;
- поиск `bits/stdc++.h`, `gets()`, `void main()`, возможного присваивания в условии `if`, повторных `#include`, подозрительного `delete`, неинициализированных переменных;
- информационное замечание о длинных строках;
- настройка анализа при изменении и максимальной длины строки.

> Это учебный лексический анализатор, а не полноценный компилятор. Он не строит AST и может выдавать ложные срабатывания на сложном C++ коде.

## Требования

- Visual Studio Code 1.85 или новее;
- Node.js и npm;
- TypeScript и типы VS Code устанавливаются через npm.

## Запуск в режиме разработки

```bash
npm install
npm run compile
```

Откройте папку проекта в VS Code, нажмите `F5` (Run Extension). В новом окне Extension Development Host откройте файл `.cpp`.

Для ручного анализа откройте палитру команд (`Cmd+Shift+P` на macOS) и выберите `C++ Code Checker: Analyze Current File`. Горячая клавиша: `Cmd+Option+A` на macOS.

## Настройки

- `cppCodeChecker.checkOnChange` — автоматически проверять файл при изменении (по умолчанию `true`).
- `cppCodeChecker.maxLineLength` — рекомендуемая максимальная длина строки (по умолчанию `100`).

## Структура проекта

- `src/extension.ts` — регистрация расширения, обработчики событий, анализатор и публикация диагностик.
- `docs/ARCHITECTURE.md` — архитектура и алгоритмы.
- `docs/REPORT.md` — основа отчёта по лабораторной работе.

## Использованные технологии

TypeScript, VS Code Extension API, регулярные выражения, `Set`, массив диагностик.

## Использование ИИ

При подготовке учебного проекта использовался ChatGPT для помощи с проектированием, подготовкой типового кода и документации. Автор должен самостоятельно проверить, запустить, протестировать и понимать представленные решения.
