## 1. Цель работы

Цель лабораторной работы — изучить механизм расширения среды разработки и реализовать собственный плагин, добавляющий функциональность в IDE.

## 2. Техническое задание

Разработать расширение для Visual Studio Code, выполняющее статический анализ открытого файла C/C++. Плагин должен:

- запускать анализ вручную через команду;
- автоматически анализировать документ при открытии, сохранении и изменении;
- находить набор распространённых потенциальных ошибок и замечаний стиля;
- показывать результаты в редакторе и панели Problems;
- позволять отключить анализ при изменении и настраивать максимальную длину строки.

## 3. Среда разработки и технологии

В качестве IDE выбрана Visual Studio Code. VS Code поддерживает расширение функциональности через Extension API. Расширение описывается манифестом `package.json`, в котором указываются идентификатор, версия, точка входа, команды, горячие клавиши и настройки. Исполняемая логика написана на TypeScript и компилируется в JavaScript.

Для отображения результатов используется API диагностик: `languages.createDiagnosticCollection`, `Diagnostic` и `DiagnosticSeverity`. События редактора позволяют запускать проверку при открытии, сохранении и изменении документа.

## 4. Архитектура

Плагин состоит из точки входа, обработчиков событий, предобработчика текста, анализатора правил, массива результатов и адаптера вывода диагностик. Схема подробно приведена в `ARCHITECTURE.md`.

Сначала текст документа считывается из VS Code. Комментарии и строковые литералы маскируются, чтобы регулярные выражения не принимали текст внутри них за исходный код. Затем выполняются правила проверки. Найденные замечания сохраняются в массив `Issue`, сортируются по позиции и преобразуются в объекты `vscode.Diagnostic`.

## 5. Реализованные проверки

- использование нестандартного заголовка `bits/stdc++.h`;
- использование небезопасной функции `gets()`;
- объявление `void main()`;
- вероятное присваивание вместо сравнения в условии `if`;
- подозрительное освобождение памяти через `delete`;
- объявление переменной базового типа без начального значения;
- повторное подключение одного заголовка;
- превышение заданной длины строки;
- использование `using namespace std`.

Проверки являются эвристическими и не заменяют компилятор.

## 6. Структуры данных и алгоритмы

Для хранения результатов используется массив объектов `Issue`. Для поиска повторных подключений используется множество `Set<string>`. Перед проверками выполняется посимвольное маскирование комментариев и литералов с сохранением позиций. Результаты сортируются по строке и столбцу. Если `n` — длина текста, а `k` — количество найденных замечаний, предобработка и проверки имеют линейную сложность по `n` при фиксированном числе правил, сортировка — `O(k log k)`.

## 7. Инструкция по запуску и проверке

1. Установить Node.js и Visual Studio Code.
2. Открыть папку проекта в VS Code.
3. Выполнить `npm install`.
4. Выполнить `npm run compile`.
5. Нажать `F5` для запуска Extension Development Host.
6. В открывшемся окне создать или открыть файл `.cpp`.
7. Внести код с проверяемыми конструкциями либо выполнить команду `C++ Code Checker: Analyze Current File`.
8. Посмотреть результаты в панели Problems.

## 8. Использование искусственного интеллекта

При подготовке проекта использовался ChatGPT для помощи с проектированием, подготовкой типового кода и документации. Итоговый код должен быть проверен и запущен автором; автор должен понимать назначение компонентов и ограничения эвристического анализа.
